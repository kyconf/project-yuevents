# Definition of Done

A feature is considered **Done** when it meets the following criteria:

---

## Functionality
- The feature’s core functionality works as described in the **user story** and **acceptance criteria**.  
- It can be demonstrated end-to-end on a local or staging environment **without manual setup**.

---

## Code Quality
- Code builds without errors.  
- Code has been **peer-reviewed** and merged into the main branch.

---

## Testing
- The feature has been tested manually for **edge cases** and **core use cases**.

---

## UI/UX
- The user interface matches the design mostly (or the agreed prototype).  
- The feature is **responsive** and **accessible** on standard viewports (desktop + mobile).

---

## Data & Backend
- APIs, database queries, and schemas work correctly and efficiently.  
- **Error handling** and **loading states** are implemented.

---

## Documentation
- Relevant documentation (README, API spec, or feature notes) has been updated.  
- The team understands how to **test and use the feature**.

---

## Deployment
- The feature is integrated into the main app build and can be deployed successfully.  
- **Environment variables/configuration** are properly handled.
